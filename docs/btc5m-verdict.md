# btc5m 纯 maker 刷量：可行性裁决

日期：2026-11-24
范围：Polymarket BTC 5m Up/Down，1,400 USD 级别本金，纯 maker，目标是低磨损、正利润、靠返点。

## 裁决

**当前 btc5m 不适合小资金纯 maker 刷量。** 主要约束不是返点小，而是成交本身很难在不被逆向选择的情况下发生。

三条结构事实：

1. **没有挂单奖励。** 5m Up/Down 的 `rewards_config` 为空，Crypto TWAP 奖励计划已结束。
   挂单不成交就没有收益，成交才有 maker wV。
2. **maker 返点只占价差的一小部分。** 50c 处 Tier 1–Tier 4 返点是名义的 0.075%–0.375%，
   约等于 2c 配对价差的 3.75%–18.75%。一次 5c 单边错单就能抵消多组配对。
3. **1c tick 的买盘没有空档。** 采样窗口的 best bid/ask 价差正好 1c；新单无法在 best bid 之上加价
   而不穿价。best bid 前方通常有 150–2,500 股；从 mid−1c 查到 mid−19c，每一档都有挂量。
   20 股新单永远在队尾。

模拟器在部分窗口给出 **queue 模型 0 次配对**；`touch` 模型才有成交，但它假设新单在队首，
和盘口不符。没有成交，就没有返点；强行提高成交率只能穿价（taker 费 + 价差）或持有单边。

截至 08:45Z 的部分样本（4 个已结算且有报价的窗口）：`queue` 在 1c/2c/3c 全部 0 配对；
`touch` 在 1c/2c 各 1 次配对（25%），1c 的净 `net_bps` 约 -1,735。样本太小，不能当收益预测，
但方向与队列观察一致：连乐观的 `touch` 都没有正收益。

## 为什么不是“参数没调好”

- 加宽价差不改善排队：`mid−2c`、`mid−3c` 的前方可见量比 `mid−1c` 更大，因为深档挂量更多。
- 缩小价差没有空间：价差已经是 1c，再缩小就穿价。
- 增大 size 只会让你在队尾排得更久，不会跳到队首。
- 降低延迟不能改变队列位置，只能在别人撤单/被吃完时抢补位；这需要实测，且竞争激烈。

## 什么情况下裁决会改变

1. **你成为某个新价格档的第一个挂单**，并且有足够快的补位速度。需要实测“补位成交率”，
   不能假设。
2. **你有 Chainlink TWAP 的实时访问**，能做最后 30–60 秒的方向 edge（Lane T）。
   这不是纯 maker 刷量，是有尾部的方向策略。
3. **Polymarket 重新开放 5m/15m 挂单奖励**，且奖励足够覆盖单边损失。
4. **你有合作方的高阶 maker 费率/返点**，返点大到可以覆盖单边损失；当前公开规则下没有。

## 建议

- 不要用 20 股、1c 半价差在 btc5m 上跑 Lane P。它会重复 ADR 0013 的单边亏损，而且成交率更低。
- 如果坚持 btc5m，先做 Lane T：申请 Chainlink key，重建 price to beat，做 T−30s 到 T−5s 的
  方向检验；用模拟器验证 edge 扣掉 taker 费后仍为正。
- 如果目标是返点，回到有奖励的市场（Lane A），不要在 btc5m 上刷。
- 继续用 `btc5m/recorder.py` 录多日数据，验证“补位成交率”和“OKX 领先 1–2 秒”是否稳定；
  这两件事决定 btc5m 是否还有 maker 空间。
